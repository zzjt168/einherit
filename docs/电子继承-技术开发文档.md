## 二、系统总体架构

### 2.1 逻辑分层

```text
┌─────────────────────────────────────────────┐
│  iOS 壳（WKWebView） mobile/ios/EInherit     │  默认打开 https://einherit.cn/
├─────────────────────────────────────────────┤
│  静态壳 static/（index.html · app.js · css） │
├─────────────────────────────────────────────┤
│  HTTP API  server/app.py（ThreadingHTTPServer）│  0.0.0.0:8877
├─────────────────────────────────────────────┤
│  领域/存储   server/db.py → SQLite           │  data/legacy.db
│  上传物      data/uploads/auth_videos/       │
└─────────────────────────────────────────────┘
```

### 2.2 端到端数据流（摘要）

1. 浏览器 / iOS WebView 加载静态壳 → 调 `/api/*` JSON  
2. `app.py` 路由 → `db.py` 读写 SQLite / 落盘授权视频  
3. 高风险：报备逾期 → `grace_hours` 冷静期 → 外呼模拟日志 → `manual_review`（不宣布身故）  
4. 善后工单：`auth_videos` 三勾齐（问候/授权/思路）→ 才允许 `aftercare_jobs` 入库  
5. 交割：`legacy_items` + 快照 → `/export/handover.html` 打印

## 三、领域模型与产品模块设计

> 电子继承按**产品模块 + 状态机**写，不硬套多租户。

### 3.1 模块地图（灵魂不可删改 · `.cursorrules`）

| # | 模块 | 一句话 |
|---|------|--------|
| 1 | 电子继承 / 交割 | 销毁 / 销售变现 / 转赠；设备归谁、出厂重置、照片/聊天是否消除 |
| 2 | 医旅 | 国内外医院筛选 + 意向单 |
| 3 | 电子资产备忘 | 账号与处理预案（优先存处置指引） |
| 4 | 会员 ¥365 + 生存报备 | 先打本人，再备用联系人 |
| 5 | 差旅预存 ≥¥2000 | 断缴原路退（演示账本） |
| A | 个人公司化五部门 | 生产 / 财务 / 知识产权 / 行政 / 董事会 |
| B | 自保建议（七宗罪） | 危害序：色欲→暴食→贪婪→懒惰→暴怒→嫉妒→傲慢 |
| C | 急症前清册 | ICU/入院前一键包（`ICU_PACK` 4 条） |
| D | 善后工单 | 删数据·变卖·上门；**先授权视频** |
| E | 执行人加盟 | 区域善后意向收集 |
| F | 受益人 / 紧急取用 / 审计 / 快照 | P0.4 开源对标落地 |

### 3.2 首页入口顺序（`PRODUCT_PLAN.md`）

今日报备 → 急症前清册 → 善后工单 → 电子继承 → 个人公司化 → 自保 → 资产备忘 → 医旅 → 会员 → 差旅预存 → 交割手册 → 执行人加盟。

### 3.3 高风险状态机（【必须】先图后码）

#### 3.3.1 生存报备引擎（手册 + `evaluate_escalation`）

```text
[ok] --到期未报备-->（先检查 grace_hours 冷静期）
         | 仍在冷静期 → [grace]（暂不外呼）
         v
[calling_self]  （演示：接通则回到 ok；simulate_unreachable 则继续）
         |
         v
[calling_backup] → 通知备用联系人（最小必要话术，不宣布身故）
         |
         v
[manual_review] →（P1）冷静期人工复核后 → [execution_queued]
```

代码现状（`db.evaluate_escalation`）：

- 未逾期 → `ok`  
- `checkin_in_grace` → `grace`  
- `simulate_unreachable=true` → 记 `call_log`，状态 `calling_backup` 后立刻 `manual_review`  
- 默认演示路径 → 本人「已确认安全」并 `do_checkin`  

【必须】外呼须用户书面授权；话术不直接宣布身故。  
【待确认】真实语音外呼供应商、录音留存周期、`execution_queued` 人工台字段。

#### 3.3.2 会员断缴 → 差旅预存退回（`lapse_membership`）

```text
[member_active + travel_balance>0]
        --断缴-->
[refunded]（balance=0，ledger: travel_refund）或 [lapsed_no_balance]
```

【必须】会员费与差旅预存分账；断缴只退预存未消费余额。  
【待确认】微信/支付宝真实退款 API、对账与失败态 `refund_failed` 人工台（手册有、代码演示路径尚未分支 `refund_failed`）。

#### 3.3.3 紧急取用（`emergency_access`）

受益人申请 → `pending`（默认等待 `wait_days=7`）→ 主人 `approve` / `deny`；另有 `tick_emergency` 到期自动放行逻辑。  
【必须】不因超时自动开放全部资产；只走申请流。

#### 3.3.4 善后授权视频门槛（【必须】）

`auth_videos` 同时满足 `has_greeting` + `has_authorize` + `has_plan` → `auth_video_ready`；否则 `add_aftercare` 抛错。  
上传：multipart ≤120MB，扩展名 mp4/mov/m4v/webm/avi；或 JSON `demo:true` 占位（自检用）。

## 七、关键业务能力设计

### 7.1 会员 + 生存报备（P0 演示 / P1 真实外呼）

- 开通：`activate_membership` → `member_until` ≈ 一年  
- 打卡：重置 `last_checkin_at` + `escalation_state=ok`  
- 【必须】冷静期默认 `grace_hours=72`  
- 【待确认】支付通道与发票

### 7.2 电子继承交割

字段：`title/category/action/beneficiary/factory_reset/clear_photos/clear_chats/dept/notes`。  
action 语义：销毁 · 销售变现 · 转赠（及清册模板中的变体）。  
导出：`/export/handover.html`；快照：`handover_snapshots`。  
【建议】P1 正式 PDF 版式与电子签。

### 7.3 急症前清册 / 善后工单 / 授权视频

对标王洋律师案例结构（手册 §0.35）：病友语境 → 授权视频 → 工单 → 差旅 → 失联升级。  
【必须】未授权不擅删；无冷静期不自动执行交割。

### 7.4 差旅预存

建议最低 ¥2000；与会员分账；断缴退余额。  
【待确认】消费核销明细 UI 与财务对账。

### 7.5 医旅

信息中介；种子医院库 + 意向单。  
【必须】不做疗效承诺。  
【待确认】BD 医院库与顾问工单（P2）。

### 7.6 个人公司化 / 七宗罪 / 执行人加盟

见 §三常量；加盟写入 `executor_leads`（姓名必填）。

### 7.7 受益人紧急取用与审计

见 `docs/开源对标学习.md`：不宣布身故、冷静期、等待期可拒、可审计、可打印。
